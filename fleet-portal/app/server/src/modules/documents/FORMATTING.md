# Оформление XLSX по июльским образцам

Эталон счёта — лист «39 коп» (5 554 372,39 ₽). Каталог `referenceLayouts.ts` содержит только оформление, без клиентских данных и формул. Четыре формы: дневной акт, итоговый акт, реестр и счёт.

`layout.ts` создаёт лист с исходными стилями, объединениями, размерами и параметрами печати. В `xlsx.ts` подставляются значения в существующие ячейки. Не присваивать `row.values`: ExcelJS при этом теряет ранее установленные стили.

Сохранять документы через `writeDocumentWorkbook`, как это делает `routes.ts`. Прямой `workbook.xlsx.writeBuffer()` теряет исходные признаки автоматической высоты строк и базовый шрифт Normal. Последний влияет на физическую ширину колонок при печати. Сериализатор восстанавливает эти параметры в OOXML, включая параметры страницы и bestFit.

Для 24 дневных образцов сохранены индивидуальные варианты оформления, выбираемые по номеру акта. Для последующих номеров используется базовый вариант. При другом числе строк таблица расширяется, а итоговые строки, подписи и область печати сдвигаются. Точное постраничное совпадение проверено на структуре июльских образцов; произвольный объём и длина новых данных могут менять переносы.

Проверки: `npm test` и `npm run build` из каталога сервера. `test/documents-layout.test.ts` проверяет оформление после сохранения и повторного чтения XLSX, разные размеры таблиц, базовый шрифт и автоматическую высоту строк.

## Пересборка каталога

`referenceLayouts.ts` — генерируемый файл, вручную его не редактировать. Экстрактор находится в `scripts/extract-document-layouts.cjs`; дополнительный Python-скрипт для форматирования больше не требуется. Зависимости устанавливаются обычным `npm ci` в каталоге сервера.

Из каталога `fleet-portal/app/server`:

```sh
npm run layouts:extract -- '/путь/к/каталогу/эталонов'
npm test
npm run build
```

Необязательный второй аргумент задаёт другой выходной файл, например `/tmp/referenceLayouts.ts`, для сравнения перед заменой каталога. Исходные XLSX не изменяются. В консоль не выводятся значения ячеек.

В каталоге эталонов нужны четыре исходных файла с именами из массива `specs` экстрактора. Файлы с реальными реквизитами не включены в репозиторий: для воспроизведения нужны внешние исходники или подготовленные обезличенные XLSX с тем же оформлением. Имена файлов, индекс листа, границы строк данных, последняя строка и число колонок заданы в `specs`. Для счёта дополнительно проверяется имя листа «39 коп». Индексы листов и номера XML-листов рассчитаны на структуру исходных июльских книг; при перестройке книг эту привязку тоже необходимо проверить.

Для изменения только шрифтов, рамок, ширин и других параметров оформления отредактируйте копии исходных XLSX, запустите экстрактор и проверьте diff. Для дневных актов измените все нужные листы: у них индивидуальные варианты. Затем сформируйте документы и сравните их печатный вид с новыми эталонами.

Если меняется структура формы (расположение полей, столбцов или строк), одной пересборки недостаточно: обновите `specs`, привязки ячеек в `xlsx.ts`, при необходимости логику сдвига в `layout.ts` и ожидания тестов. Тексты и формулы экстрактор не переносит; их изменение выполняется отдельно в генераторе. Это каталог оформления, а не универсальный движок XLSX-шаблонов.
